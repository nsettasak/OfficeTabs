# Publishing on GitHub

Use **this directory** as the repository root (the directory containing Cargo.toml
and README.md), not its parent workspace. Include `.github/`, `.cargo/`, `assets/`,
`src/`, `tests/`, `vendor/` and the root text/build files. Do not upload `outputs/`,
installed application files, old backups or generated folders.

## Before the first public push

- Preserve THIRD_PARTY_NOTICES.md, including the owner-confirmed AI-generated icon
  provenance and the vendored dependency licenses.
- Run `python privacy_audit.py --source`; review all intended files for secrets and
  personal information. Automated pattern checks are not a complete secrets audit.
- Use a GitHub account/display name you are comfortable publishing. File cleanup
  does not hide the repository owner. Enable GitHub email privacy and use the exact
  noreply address shown in account settings for commit email; do not invent one.
- In GitHub, create an empty repository called `OfficeTabs`, choose Public, and do
  not generate another README or license. Public copies and forks may persist.
- The project is a **preview**, not a production-ready or security-reviewed release.

## Upload source with Git

From this directory, run the following yourself. Replace the placeholders with
your chosen public identity and repository URL. Do not paste a token into a URL.

```powershell
git init -b main
git config user.name "YOUR_PUBLIC_DISPLAY_NAME"
git config user.email "YOUR_GITHUB_NOREPLY_ADDRESS"
git add .
git diff --cached --stat
git diff --cached --check
git status --short
# Review staged contents before continuing.
git commit -m "Initial OfficeTabs public preview"
git remote add origin https://github.com/YOUR_ACCOUNT/OfficeTabs.git
git push -u origin main
```

Use Git Credential Manager or GitHub's normal authentication flow. No account,
remote, commit or push has been created automatically by these preparation files.
Check Actions after pushing. Enable branch protection and private vulnerability
reporting in repository settings; those settings cannot be enabled by files alone.

## Optional preview release

Run the full build/audits locally and perform docs/TESTING.md with disposable Office
documents. Record actual results, including failures. Update all version metadata
and ProductCode together when changing the release version; preserve the UpgradeCode
and Office COM class IDs. Existing 0.33 binaries predate repository-preparation
changes, so rebuild before distributing a new build from this source tree.

Use the GitHub Releases UI to create a **pre-release**, upload the reviewed single
`Setup.exe`, and describe known limitations. Do not claim Authenticode signing.
Provide a SHA-256 checksum generated from that exact file if distributing it.
Do not upload MSI intermediates, logs or a developer ZIP. `package.py` creates no
ZIP unless `--final` is explicitly supplied after the owner declares a final release.
GitHub itself provides automatic source archive links for tags; these are a platform
feature, not a ZIP generated by our build scripts. CI does not publish releases or
upload artifacts automatically.
